# ig-media

블로그·투자 판정 워크플로 저장소.

## 어드바이저 시스템

4개 계좌 어드바이저가 **하나의 5단계 프로토콜**을 공유한다.

```
P1 조사 → P2 반대논리검토 → P3 투자 → P4 공개 → P5 사후평가
                  ↑ 게이트                        ↓
                  └────────── 기록부 ────────────┘
```

| 스킬 | 계좌 | 쓰는 때 |
|---|---|---|
| `advisor-pension` | PEN 연금저축 | 연금저축에 뭘 담을지 |
| `advisor-isa` | ISA | ISA 개설하고 뭘 살지, 만기 처리 |
| `advisor-global` | GLB 해외 일반계좌 | 해외 개별종목 검토 |
| `advisor-coordinator` | ALL | 전체 점검, 계좌 간 배분, 기록부 감사 |

계좌별로 다른 것은 **P1 입력 항목과 P3 실행 규칙뿐**이다. P2·P4·P5는 전부 공용이며
`claude/advisor/PROTOCOL.md` 한 곳에만 적혀 있다.

## 파일

| 경로 | 내용 |
|---|---|
| `claude/advisor/PROTOCOL.md` | **5단계 공용 규칙.** 여기부터 읽는다 |
| `claude/advisor/계좌-제약.md` | 계좌별 제도 제약. 세법 수치는 `[확인필요]`로 비어 있다 |
| `claude/advisor/프로필.md` | 운용 전제. **미작성 상태 — 채우기 전에는 P3로 가지 않는다** |
| `claude/advisor/templates/` | 조사노트 · 반대논리검토서 · 사후평가서 |
| `claude/판정기록부.md` | 전 계좌 공용 원장. 계좌별로 나누지 않는다 |
| `claude/post-index.md` | 발행 이력 (`naver-stock-blog` 규약) |

## 설계상 핵심 두 가지

1. **P2는 게이트다.** 4문항 중 2개 이상을 서면으로 기각하지 못하면 P3로 가지 않는다.
   "검토했다"는 통과가 아니라 기각 사유가 통과다.
2. **`공개ID` 한 칸이 P4와 P5를 잇는다.** 기록부의 이 칸이 비면
   "그때 그 글의 주장이 맞았나"를 되짚을 방법이 사라진다. 무효화 조건이 발동한 공개본의
   정정 공개는 의무다.

## 기존 스킬과의 관계

`nasdaq-monthly-allocation`(P1 하위 절차) · `nasdaq-event-trigger`(P5 소집기) ·
`naver-stock-blog`(P4 원고) · `tistory-auto-publish`(P4 발행)는 규칙을 그대로 유지한다.
이 시스템은 그 위에 **판정ID와 기록부라는 공통 축**을 얹어 서로를 연결한다.

3. 계좌에 맞는 어드바이저를 호출한다
