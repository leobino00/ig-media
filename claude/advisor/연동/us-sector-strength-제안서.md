## 0. 한 줄 요약

**미국 섹터의 QQQ 대비 상대강도·분면·폭을 매주 금요일 종가 기준으로 관측해, 판단 없이 사실만 `brief.md` + `brief.json`으로 내는 프로그램.**
소비자는 사람이 아니라 어드바이저의 예약 세션(루틴)이다. 그래서 형식·기준일·출처·결측 규칙이 내용만큼 중요하다.

## 1. 배경 — 발주자가 누구이고 무엇을 하는가

이 문서를 읽는 세션은 어드바이저를 모른다는 전제로 쓴다. 필요한 만큼만 적는다.

### 1-1. 어드바이저 워크플로우

한 개인의 4개 계좌(연금저축·IRP·ISA·해외계좌)를 운용하는 판정 시스템이다. 핵심 규칙 다섯 개:

| 규칙 | 내용 | 이 프로그램에 미치는 영향 |
|---|---|---|
| **벤치마크 = QQQ 바이앤홀드** | 모든 판정을 QQQ 대비로 채점한다. 절대수익이 +여도 QQQ에 못 미치면 실패 | **상대강도의 분모가 QQQ여야 한다** (R1) |
| **3층 구획** | 코어(나스닥100 패시브) · 위성(개별종목 최대 5, 액티브) · 방어(파킹) | 이 프로그램은 **위성**의 재료다. 코어는 판단 없이 시가총액 가중이라 섹터 정보를 쓰지 않는다 |
| **5단계 프로토콜** | P1 조사 → P2 반대논리검토(게이트) → P3 투자 → P4 공개 → P5 사후평가 | 산출물은 **P1의 「사실」 표**에 들어간다. 판단은 P2에서 사람과 어드바이저가 한다 |
| **결측은 추정하지 않는다 · 모든 수치에 출처 · 사실과 해석 분리** | 프로토콜 P1-2·3·4 | 출력 형식의 근거 (R7) |
| **검증 전 신호로 돈을 움직이지 않는다** | 타이밍 엔진조차 6회 기록 전용. 월간 지표 구성은 20회 전 변경 금지 | 이 프로그램은 **판정 규칙이 아니라 관측 입력**이다. 월간 엔진에 지표를 추가하지 않는다 (§3) |

### 1-2. 위성이란 무엇인가 — 이 프로그램의 진짜 고객

위성은 해외계좌(GLB)에서만 담는 개별종목이다. 규칙:

- 최대 5종목. 편입하려면 **"왜 QQQ보다 나은가"** 를 서면으로 써야 하고, P2의 반대 명제에 항상 「그냥 QQQ를 사라」가 들어간다.
- 무효화 조건은 **날짜 또는 관측 가능한 사실**이어야 한다. 「분위기가 나빠지면」은 무효화 조건이 아니다.
- 주간 트리거 점검에 **T4 위성 규칙**이 있다: 평단 대비 **−15% 손절 / +30% 이익실현 검토**.
- 지금은 **0/5로 비어 있고**, 첫 위성 판정은 **2027년 2~3월**(세액공제 환급액 792,000원 입금 시)이다.

이 프로그램이 완성되면 위성 판정 P1에서 "후보 종목이 속한 섹터가 QQQ 대비 어느 분면에 몇 주째 있는가"를 출처 있는 사실로 첨부할 수 있다. **그것이 첫 번째 용도이고, 5개월 뒤 실제로 쓰인다.**

## 4. 요구사항 — 각각 이유와 함께

### R1. 상대강도의 분모는 QQQ다 (필수)

모든 섹터 가격을 **QQQ 종가로 나눈 비율**에서 출발한다. SPY가 아니다.
이유: 위성 판정의 질문이 "QQQ보다 나은가"이고 P5 채점도 QQQ 대비다. 분모가 다르면 산출물 전체가 워크플로우와 맞지 않는다.

### R2. 유니버스 = S&P 11개 GICS 섹터 + 나스닥 하위섹터 3개 (필수)

| 구분 | 티커 | 이유 |
|---|---|---|
| GICS 11 | XLK · XLV · XLF · XLY · XLC · XLI · XLP · XLE · XLU · XLRE · XLB | 데이터 깨끗·무료·표준. 위성 후보가 나스닥 밖 종목일 수 있어 S&P 전체 범위 필요 |
| 나스닥 하위 3 | 반도체 **SMH**(불가 시 SOXX) · 소프트웨어 **IGV** · 바이오 **XBI** | QQQ의 절반이 기술주라 11개로는 QQQ 내부 분화가 안 보인다 |

14행. 이 이상 늘리지 않는다 — 출력이 길어지면 루틴이 읽는 비용이 는다 (R11).

### R3. 나스닥100 구성종목 폭 지표 (필수)

| 지표 | 정의 | 이유 |
|---|---|---|
| `pct_above_sma200` | 나스닥100 구성종목 중 종가 > 200일 단순이동평균인 비율(%) | 현재 폭 지표가 QQQE/QQQ 하나뿐이라 약하다. 구성종목 수준 폭이 없다 |
| `nh_nl_ratio` | 최근 5거래일 내 52주 신고가 종목 수 ÷ 신저가 종목 수 (신저가 0이면 `null` + 신고가 수 병기) | 〃 |

구성종목 목록 출처 순서: ① Invesco QQQ 보유종목 CSV(일일 갱신) → ② 공식 나스닥100 페이지 → ③ 둘 다 실패 시 **결측**. 어느 출처를 언제 받았는지 json에 남긴다. Wikipedia는 최후 수단이고 등급 C로 표기한다.

### R4. 보유 위성 섹터 태깅 (필수, 기본 켬)

어드바이저가 `입력/holdings.json`을 쓴다(§8-1 계약). 프로그램은 각 티커의 섹터를 붙여 `brief.json.holdings[]`에 돌려준다.
이유: 국내판에서는 국내 보유 종목이 없어 무의미했지만, 여기서는 GLB 위성이 이 태그를 T4 점검 때 직접 읽는다.
티커 → 섹터 매핑 출처: Yahoo `quoteSummary` `assetProfile.sector` (B등급). 실패 시 `null`.

### R5. 이벤트 플래그 — 판정하지 말고 표시만 (필수)

| 플래그 | 정의 | 왜 이 값인가 |
|---|---|---|
| `quadrant_changed` | 이번 주 분면 ≠ 지난주 분면 | 무효화 조건으로 사전등록 가능한 이산 이벤트 |
| `weeks_in_quadrant` | 현재 분면 연속 주수 | "N주 연속" 조건에 쓴다 |
| `rs_dd_15` | 섹터/QQQ 비율이 26주 고점 대비 −15% 이하 | **T4 손절 임계치와 같은 숫자.** 섹터 단위 조기 경보 |
| `rs_up_30` | 섹터/QQQ 비율이 26주 저점 대비 +30% 이상 | T4 이익실현 검토 임계치와 같은 숫자 |

발동 여부의 판정은 어드바이저가 한다. 프로그램은 `true/false`만 낸다. 어드바이저의 `fred-latest.json`이 `"T1a_(<=-10%)": false` 형태로 플래그를 값 옆에 두는 것과 같은 방식이다.

### R6. 출력은 `brief.md` + `brief.json` 이원 (필수)

md는 사람용(80행 이내), json은 루틴용. 형식은 §6. 국내판과 키 이름을 맞춘다.

### R7. 기준일·생성시각·출처·등급·결측·한계 (필수)

| 항목 | 규칙 |
|---|---|
| `as_of` | 마지막 거래일(금요일). 생성시각과 별도 |
| `generated_at` | ISO 8601, 타임존 포함 |
| 출처 | 시리즈·URL·등급. Yahoo 차트 = **B**, Invesco 보유종목 = **A−**, Wikipedia = **C** |
| 결측 | 값은 `null`, 파일 머리 `missing[]`에 이름 나열 |
| 한계 고정 문구 | md 꼬리에 매번. §9의 검증 결과를 그대로 옮긴다. 결과가 나쁘면 나쁜 대로 적는다 |

이유: 어드바이저 시스템은 "한 번 적힌 결측·추정이 사실로 굳는" 오류를 두 번 겪었다. 매 산출물에 한계를 반복 명기하는 것이 재발 방지책이다.

### R8. 데이터 소스 = Yahoo 차트 API (필수), 라이브러리 최소

```
GET https://query1.finance.yahoo.com/v8/finance/chart/{SYMBOL}?range=2y&interval=1d
User-Agent: Mozilla/5.0
```

어드바이저 수집기가 GitHub Actions 러너에서 이 경로로 성공하고 있다. `range=2y`는 26주 평균 워밍업용.
표준 라이브러리(`urllib`, `json`, `csv`, `statistics`)로 충분하다. pandas 등은 써도 되지만 러너 설치 시간이 는다.
stooq는 쓰지 않는다 (봇 차단 확인됨).

### R9. 주기와 마감 (필수)

- 매주 **금요일 미국 장 마감 후**, 늦어도 **토요일 07:30 KST(금 22:30 UTC)** 이전 완료.
- 그 시각에 어드바이저 수집 워크플로우가 돌고, 토 10:00 KST에 루틴이 읽는다. 늦으면 그 주는 결측 처리되며 오류는 아니다.

### R10. 착지 경로 (필수)

최종 위치는 어드바이저 저장소의 `claude/advisor/월간판정/입력/`:

```
sector-us-latest.md
sector-us-latest.json
sector-us-YYYY-MM-DD.json   (주간 스냅샷, 덮어쓰지 않음)
```

저장소 위치 관계(§11 Q1)에 따라 직접 쓰거나 raw URL로 받아온다.

### R11. 크기 (필수)

`brief.md` ≤ 80행 · `brief.json` ≤ 100 KB. 궤적·시계열은 json에만, md에는 최신값과 주간 변화량만.
이유: 루틴 프롬프트가 "사용량을 아끼기 위해 간결하게"를 명시한다.

### R12. 국내판과의 일관성 (권장)

키 이름·분면 명칭·한계 문구 형식을 `kr-sector-strength`와 맞춘다. 두 파일을 나란히 읽는 세션이 다른 스키마를 두 번 배우지 않게.

## 5. 계산 정의 — 국내판에 정의가 있으면 그것을 우선한다

주간 종가(금요일) 기준. 일봉을 받아 주봉으로 집계한다.

| 기호 | 정의 |
|---|---|
| `R(t)` | 섹터 종가 ÷ QQQ 종가 |
| `rs_ratio` | `R(t) / mean(R, 최근 26주)` — 1.00이 QQQ와 동행, >1 상대 강세 |
| `rs_momentum` | `rs_ratio(t) / rs_ratio(t−4주) − 1`, % |
| `quadrant` | `rs_ratio > 1 & rs_momentum > 0` → **leading**(주도) · `>1 & ≤0` → **weakening**(약화) · `≤1 & ≤0` → **lagging**(후행) · `≤1 & >0` → **improving**(개선) |
| `rs_chg_4w` | `rs_ratio(t) − rs_ratio(t−4주)` |
| `rs_dd_from_26w_high` | `R(t) / max(R, 26주) − 1`, % → `rs_dd_15 = (≤ −15)` |
| `rs_up_from_26w_low` | `R(t) / min(R, 26주) − 1`, % → `rs_up_30 = (≥ +30)` |
| `dispersion` | 14개 `rs_ratio`의 표준편차. `dispersion_pctile`은 과거 2년 대비 백분위 |
| `pct_above_sma200` | R3 |
| `nh_nl_ratio` | R3 |

경계값(=1, =0)은 위 표대로 처리하고 문서에 그대로 적는다. 정의를 바꾸면 버전을 올리고 `brief.json.version`에 반영한다 — 어드바이저는 소급 채점을 하지 않으므로 버전이 바뀐 시점을 알아야 한다.

## 8. 연동 계약

### 8-1. 들어오는 것: `holdings.json` (어드바이저 → 프로그램)

어드바이저가 `claude/advisor/월간판정/입력/holdings.json`을 유지한다. 프로그램은 이 파일이 있으면 읽고, 없으면 `holdings: []`로 낸다.

```json
{"as_of": "2026-09-12", "account": "GLB",
 "satellites": [{"ticker": "XXXX", "avg_cost_usd": 0.0, "since": "2027-02-15"}]}
```

프로그램은 티커에 섹터를 붙이고, 해당 섹터의 이번 주 행을 `brief.json.holdings[]`에 복사한다. 평단·손익은 계산하지 않는다 (T4는 어드바이저가 한다).

## 9. 검증 요구 — 결과가 나빠도 그대로 적는다

국내판이 한 것과 같은 정직성으로. 최소 아래를 돌리고 README와 md 꼬리에 결과를 남긴다.

| 검증 | 방법 | 보고 형식 |
|---|---|---|
| 분면의 선행력 | 각 주 `leading` 섹터의 **4주 후 QQQ 대비 초과수익** 평균 vs 전체 섹터 평균. 2년 이상, 연도별 분리 | "연도별 6년 중 N년 양수, 평균 +x%p" 형태 |
| 폭의 선행력 | `pct_above_sma200` 하위 20% 구간 이후 4주 QQQ 수익 vs 나머지 | 〃 |
| 하락 예고 여부 | QQQ 4주 −10% 이상 하락 직전 4주의 `leading` 수·분산도가 평상시와 다른가 | 다르지 않으면 "다르지 않다"고 적는다 |
| 데이터 안정성 | 같은 기준일에 두 번 돌려 값이 같은가. Yahoo 조정종가 소급 변경 여부 | 재현 불가 항목 명시 |

**금지:** 잘 나온 창만 골라 보고하기, 임계치를 결과 보고 조정하기.
이 시스템의 월간 엔진이 "소표본에서 가중치를 만지는 것이 이 유형 모델이 실패하는 가장 흔한 경로"라고 적어 둔 이유와 같다.
