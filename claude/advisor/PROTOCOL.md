# 어드바이저 공용 프로토콜 — 조사 → 반대논리검토 → 투자 → 공개 → 사후평가

## 이 문서의 위치

`advisor-pension` / `advisor-isa` / `advisor-global` / `advisor-coordinator` 네 어드바이저는 **전부 이 5단계를 통과한다.**

계좌별로 다른 것은 **P1의 입력 항목**과 **P3의 실행 규칙**뿐이다. P2·P4·P5는 전부 공용이다.
어드바이저 스킬 안에 이 규칙들을 복사하지 않는다. 복사본이 생기는 순간 계좌마다 기준이 갈라지고, 그때부터 계좌 간 성적 비교가 불가능해진다.

## 단계 요약

| 단계 | 이름 | 하는 일 | 산출물 | 다음 단계로 가는 조건 |
|---|---|---|---|---|
| **P1** | 조사 | 입력값 확정 | 조사노트 | 결론·확신도·근거 3개·출처 전부 존재 |
| **P2** | 반대논리검토 | 결론을 깨본다 | 반대논리검토서 | 4문항 전부 서면 기각 |
| **P3** | 투자 | 사전등록 후 실행 | 기록부 실행 행 | (종착) |
| **P4** | 공개 | 실행 이후에 글로 낸다 | 원고 + 공개ID | (선택) |
| **P5** | 사후평가 | 채점하고 남긴다 | 기록부 채점 열 | (순환) |

P4는 선택이고 나머지 넷은 필수다. **P2를 건너뛴 판정은 P3로 갈 수 없다.**

## 판정ID

모든 산출물은 하나의 ID를 달고 5단계를 함께 이동한다.

```
YYYY-MM-DD-<계좌코드>-<3자리 일련번호>
예: 2026-09-01-ISA-001
```

계좌코드: `PEN`(연금저축) / `IRP`(개인형퇴직연금) / `ISA` / `GLB`(해외 일반계좌) / `ALL`(계좌 간 배분)

ID가 없는 산출물은 기록부에 붙일 수 없다. 즉 없었던 것과 같다.

### 산출물 저장 위치

```
claude/advisor/판정/<판정ID>/
    조사노트.md            (P1)
    반대논리검토서.md       (P2)
    사후평가서.md          (P5)
```

한 판정의 산출물은 **한 폴더에 모은다.** 단계별로 폴더를 나누면 P5에서 P2를 다시 읽을 때
흩어진 파일을 찾아다니게 되고, 그러면 읽지 않게 된다.
P4 산출물(원고)은 `naver-stock-blog`의 규약을 따르되, 공개ID를 기록부에 적어 이 폴더와 잇는다.

## P1 — 조사

**목적은 판단이 아니라 입력값 확정이다.** 여기서 결론을 미리 정해두면 P2가 형식이 된다.

1. **기준일을 먼저 고정한다.** 실행 시점이 아니라 기준일 기준 최신값을 쓴다. 이 규칙이 없으면 같은 사안도 실행 시각에 따라 값이 달라져 기록 간 비교가 깨진다.
2. **결측은 추정하지 않는다.** `결측`이라고 적고 산출물에 명시한다. 추정값을 채우면 나중에 어느 근거가 틀렸는지 역추적할 수 없다.
3. **사실과 해석을 물리적으로 분리해 적는다.** 같은 문단에 섞지 않는다. 섞이면 P2에서 무엇을 공격해야 하는지가 사라진다.
4. **모든 수치에 출처를 단다.** 출처 없는 수치는 결측과 동일하게 취급한다.
5. **결론은 한 문장 + 확신도(상/중/하).** 확신도는 말이 아니라 계산으로 정한다. 기준은 각 어드바이저 스킬이 규정한다.

산출물: `claude/advisor/templates/조사노트.md`

## P2 — 반대논리검토

> 이 시스템에서 가장 자주 건너뛰게 되는 단계다. 그래서 게이트로 만들었다.

**목적은 결론을 방어하는 것이 아니라 깨보는 것이다.** "검토했다"는 통과가 아니다. **기각 사유가 서면으로 남아야** 통과다.

### 필수 4문항 — 전부 서면 답변

1. **반대 명제**
   P1 결론의 정반대를 한 문장으로 쓴다. 그것이 참이 되려면 무엇이 사실이어야 하는가? 그 사실은 지금 관측 가능한가?

2. **이미 반영됐는가**
   내 근거가 공개 정보라면 가격에 이미 들어 있다고 봐야 한다. 그럼에도 기회가 남아 있다고 보는 이유는 무엇인가?
   답하지 못하면 **그 근거는 폐기한다.** 폐기 후 근거가 3개 미만이면 P1로 되돌아간다.

3. **가장 강한 반대편 논거**
   같은 데이터로 정반대 결론을 낸 사람의 논거를 **원문 그대로** 옮긴다.
   찾지 못했으면 "찾지 못함"이라고 적는다. **지어내지 않는다.** 지어낸 약한 반대논거를 기각하는 것이 이 단계를 무력화하는 가장 흔한 방법이다.

4. **무효화 조건**
   내가 틀렸다는 것을 무엇으로, 언제 알 수 있는가? **관측 가능한 수치 + 날짜**여야 한다.
   - ✗ "실적이 나빠지면" — 무효화 조건이 아니다
   - ✓ "3분기 EPS가 $2.10 미만이면 (발표 예정일 2026-10-28)"

### 판정

| 기각하지 못한 항목 | 처리 |
|---|---|
| 0개 | 통과. 원안대로 P3 |
| 1개 | **규모 축소** — 계획 대비 절반 이하로만 P3 |
| 2개 이상 | **보류.** P3로 가지 않는다. 기록부에 `보류`로 남긴다 |

보류도 판정이다. 기록부에 남기지 않으면 나중에 같은 건을 처음부터 다시 조사하게 된다.

### 금지

- **P1 결론으로 반대논리를 반박하지 않는다.** 같은 근거를 다시 쓰는 것은 기각이 아니다.
- **무효화 조건을 사후 조정 가능한 형태로 쓰지 않는다.** "손실이 커지면"은 나중에 아무 값으로나 해석된다.
- **P3 이후에 소급 작성하지 않는다.** 체결 후에 쓴 반대논리는 검토가 아니라 변명이다.

산출물: `claude/advisor/templates/반대논리검토서.md`

## P3 — 투자

1. **체결 전에 사전등록한다.** 목표비중 / 진입 방식 / 무효화 조건(P2에서 확정한 것 그대로) / 재검토일. 넷을 적기 전에는 주문을 넣지 않는다.
2. **실행일 규칙은 계좌별 스킬이 정한다.** 정기 실행일이 아닌 날의 매매는 원칙적으로 하지 않는다.
3. **재량을 막지는 않되, 재량으로 기록한다.** 규칙 밖 매매를 하는 것 자체는 사용자의 자유다. 다만 기록부 `재량` 열에 반드시 표시한다. 재량을 막을 수는 없지만 재량으로 기록되게 할 수는 있다.
4. **사전등록 없이 체결한 건은 자동으로 재량으로 기록한다.**

## P4 — 공개

공개는 의무가 아니다. 그러나 공개하기로 했다면 아래는 전부 의무다.

1. **실행 이후에 공개한다.** 공개한 뒤에 사고팔지 않는다. 순서를 뒤집으면 독자 앞에서 자기 포지션을 띄우는 글이 된다.
2. **P2의 반대편 논거와 무효화 조건을 반드시 싣는다.** 강세 논거만 남기고 반대논리를 빼는 것을 금지한다. (`naver-stock-blog`이 "원문의 미검증·한계를 반드시 살린다"고 한 규칙의 상위 규칙이다.)
3. **보유 사실을 밝힌다.** 보유 중인 대상에 대한 글에는 보유 중임을 적는다.
4. **발행 후 `공개ID`를 기록부의 해당 판정 행에 적는다.**
   이 한 칸이 **공개와 사후평가를 잇는 유일한 고리다.** 비워두면 나중에 "그때 그 글의 주장이 맞았나"를 되짚을 방법이 없다.
   동시에 `claude/post-index.md`의 해당 글 행에 `판정ID`를 적는다. 양쪽에서 서로를 가리키게 한다.
5. 원고 작성은 `naver-stock-blog`, 발행은 `tistory-auto-publish`가 담당한다. 이 프로토콜은 **무엇이 반드시 들어가야 하는지**만 정한다.

## P5 — 사후평가

### 소집 조건 — 셋 중 하나

- 사전등록한 재검토일 도래
- 무효화 조건 발동
- 분기 정기조정

### 채점 4항목

| 항목 | 판정값 |
|---|---|
| 방향 | 적중 / 빗나감 / 판정불가 |
| 무효화 조건 | 발동 / 미발동 |
| 반대논리 | P2에서 기각했던 논거 중 실제로 실현된 것 (번호로 표기) |
| 규율 | 사전등록대로 / 재량 섞임 |

### 규칙

- **사후 데이터로 과거 판정을 다시 매기지 않는다.** 지나간 판정을 지금 알게 된 정보로 고치면 검증 기록 전체가 무효가 된다. 틀린 판정은 틀린 채로 남긴다.
- **중간 성적을 해석하지 않는다.** 계좌별 표본 20건 미만에서는 기록만 하고 규칙을 바꾸지 않는다. 소표본에서 규칙을 만지는 것이 이런 시스템이 실패하는 가장 흔한 경로다.
- **결과가 좋아도 규율 위반은 위반으로 채점한다.** 재량으로 벌었으면 그것은 규칙의 성과가 아니다. 두 열을 따로 두는 이유가 이것이다.
- **`반대논리` 열이 이 시스템의 핵심 산출물이다.** 20건이 쌓였을 때 "내가 기각한 논거가 실제로는 몇 번이나 실현됐는가"를 보면, P2가 진짜 검토였는지 형식이었는지가 그대로 드러난다.
- **공개본이 있는데 무효화 조건이 발동했다면 정정 공개는 의무다.** 조용히 넘어가지 않는다. 팔로업 글에 판정ID와 함께 무엇이 틀렸는지 적는다.
- 채점 결과는 기록부의 **같은 행에 이어 적는다.** 새 행을 만들지 않는다.

산출물: `claude/advisor/templates/사후평가서.md`

## 기록부

`claude/판정기록부.md` **한 개만 쓴다.** 계좌별로 나누지 않는다 — 나누는 순간 계좌 간 중복 노출이 보이지 않게 되고, `advisor-coordinator`가 할 일이 없어진다.

열 정의:

| 열 | 내용 |
|---|---|
| 판정ID | `YYYY-MM-DD-계좌-NNN` |
| 어드바이저 | pension / isa / global / coordinator |
| 대상 | 종목·ETF·자산군 |
| P1 결론 | 한 문장 |
| 확신도 | 상/중/하 |
| P2 판정 | 통과 / 축소 / 보류 |
| 미기각 항목 | P2 4문항 중 기각 실패한 번호 |
| 무효화 조건 | 수치 + 날짜 |
| 실행 | 체결 내용 / 미실행 |
| 재량 | O / X |
| 재검토일 | YYYY-MM-DD |
| 공개ID | 티스토리 글번호 등 / 미공개 |
| 방향 | 적중 / 빗나감 / 판정불가 / (공란=미도래) |
| 무효화 | 발동 / 미발동 |
| 실현된 반대논리 | P2 문항 번호 |
| 규율 | 준수 / 위반 |

**기록하지 않은 판정은 없었던 것과 같다.**

## 기존 스킬과의 관계

| 스킬 | 이 프로토콜에서의 역할 |
|---|---|
| `nasdaq-monthly-allocation` | `advisor-coordinator`와 `advisor-isa`의 **P1 하위 절차** (나스닥 코어 비중 산출) |
| `nasdaq-event-trigger` | 전 계좌 공용 **P5 소집기** (무효화 조건과 별개로 작동하는 급락·과열 감시) |
| `naver-stock-blog` | **P4 원고 생성** |
| `tistory-auto-publish` | **P4 발행** |

이 넷은 기존 규칙을 그대로 유지한다. 이 프로토콜은 그 위에 **판정ID와 기록부라는 공통 축**을 얹어 서로를 연결할 뿐이다.
